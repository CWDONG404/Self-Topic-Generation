# 离线模型配置

## 离线含义

本项目的“本地模式”表示任务运行时只允许访问本机 Ollama、本地 OCR、已缓存的解析模型和本地 PostgreSQL/Redis。它不会在模型失败时自动改用云端接口。

Docker 镜像、Ollama 模型和 Docling/OCR 权重仍需在首次准备时下载。完成准备后，可以断开互联网再执行任务。

## 推荐角色划分

- 蓝图模型：需要较好的中文归纳和结构化输出能力。
- 出题模型：需要稳定生成 JSON、理解证据并构造干扰项。
- 审题模型：建议与出题模型不同；资源不足时可以复用，但使用独立提示词和低随机度。
- 视觉模型：必须支持图片输入，负责流程图、截图和难以结构化的图示。
- Embedding 模型：选择适合中文的本地向量模型；更换后必须重建资料库索引。

具体模型名称不写死，设置页会读取或验证用户当前安装的模型能力。

## 宿主机 Ollama

默认容器地址是 `http://host.docker.internal:11434`。Docker Desktop 可直接使用；Linux Compose 已加入 `host-gateway` 映射。

如果 Ollama 只监听 `127.0.0.1` 且容器无法访问，需要按 Ollama 官方配置调整监听地址，并确保仅在可信本机网络开放。

## Compose 内 Ollama

CPU：

```powershell
docker compose --profile ollama up -d
```

NVIDIA GPU：

```powershell
docker compose --profile ollama-gpu up -d
```

Compose 内的 Ollama 服务名与宿主机默认地址不同。在设置页新增配置时使用 `http://ollama:11434` 或 `http://ollama-gpu:11434`，并与实际启用的 profile 保持一致。

## 视觉能力不足

没有视觉模型时，PDF/DOCX 的正文、OCR 文字和结构化表格仍可出题；纯图片内容会被标记并排除。系统必须显示这一警告，不能把图片邻近文字假装成图片理解结果。
